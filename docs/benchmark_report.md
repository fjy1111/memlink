# 阶段三 Benchmark 真实结果

## 1. 数据来源

本报告读取 `benchmarks/results/raw_runs.jsonl` 和 `benchmark_summary.json`。正式运行包含300条记录，五种配置各60条，成功率均为100%。环境为 CPython 3.11.15、Windows-10-10.0.26200-SP0、Fake LLM/Fake Embedding、seed 2026。

实验矩阵为五种配置×10轮×每轮6个任务，即每种配置60条、合计300条。该数据
专门用于可复现的协议开销、稳定性和消融分析；运行过程不访问 DeepSeek 或其他
互联网模型服务。

## 2. 总表

| 实验 | 消息 | 字符均值 | Token 均值 | JSON B | MessagePack B | P50/P95 ms | 记忆查询命中率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| text | 4 | 3420.933 | 855.650 | 8033.533 | 0 | 27.286/33.587 | 96.67% |
| structured | 9 | 4039.833 | 1010.300 | 7621.433 | 6865.533 | 48.490/61.698 | 97.22% |
| no memory | 9 | 3120.333 | 780.500 | 6633.333 | 5898.333 | 7.421/11.816 | 0% |
| no SemanticState | 9 | 3675.933 | 919.317 | 7230.433 | 6481.533 | 27.194/31.801 | 96.67% |
| no result_ref | 9 | 6188.367 | 1547.400 | 14363.767 | 13178.133 | 47.341/68.328 | 97.22% |

## 3. 消息数量

text 固定4条完整交接。structured 固定9条，包括4条 handshake 和5条业务/完成消息，因此结构化消息数更高。这是能力快照和追踪带来的明确开销。

## 4. 字符与 estimated token

完整 structured 相对 text 字符增加18.09%，估算 Token 增加18.07%。原因之一是当前 structured 字符指标统计协议中的 ID、action、capability 等所有字符串，而不只是自然语言。这一结果不支持“structured 必然减少 Token”的结论。

## 5. JSON 与 MessagePack

structured 的平均 JSON 为7621.433 B，比 text 的8033.533 B低5.13%；同一 structured 消息的 MessagePack 平均为6865.533 B。但 text 没有 MessagePack 副本，若把两类序列化量相加，structured 总负载更高。

## 6. SemanticState

完整 structured 每任务传递3次状态 ID，引用向量字节合计384 B。关闭 SemanticState 后次数、字节和状态文件增长均为0，证明开关改变了真实执行分支。

## 7. result_ref

完整 structured 每任务平均4个结果引用、0个完整结果字段。关闭 result_ref 后引用降为0，完整结果字段增至7，JSON 均值增加88.47%，MessagePack 也从6865.533 B增至13178.133 B。该消融直接证明引用减少了重复结果传输。

## 8. 共享记忆

完整 structured 平均进行3次记忆查询，查询命中率97.22%。关闭记忆后查询、命中和 SQLite 记忆增长均为0，P50明显降低，说明当前轻量任务中记忆和向量检索是主要耗时来源之一。

`memory_hit_count` 是返回记忆条数，可能大于查询数；百分比使用发生命中的查询次数计算。

## 9. 总耗时与 P50/P95

text P50/P95 为27.286/33.587 ms，structured 为48.490/61.698 ms，分别高77.71%和83.70%。在 Fake 模型非常快的条件下，SQLite、状态文件、协议校验和多策略检索的固定成本占比很高。

## 10. 完成率和错误

所有配置均60/60成功，错误率和重试数为0。结果中没有通过捕获异常伪造的成功记录。

## 11. 消融分析

- 无记忆：耗时和字符最低，但失去跨任务复用；
- 无 SemanticState：耗时接近 text，仍保留关键词/标签记忆；
- 无 result_ref：通信字节显著增加，验证引用的价值；
- 完整 structured：机制最完整，但当前时延不是最优。

## 12. 稳定性

完整 structured 连续执行60个任务：

- 成功60、失败0、异常0、重试0；
- P50/P95 为48.4905/61.69835 ms；
- SQLite 净增长6条，SemanticState 增长120组；
- 数据库句柄释放成功；
- 临时文件、后台进程残留为0；
- 临时实验目录清理成功。

## 13. 结论

当前结果证明结构化协议、非文本状态、共享记忆和消融框架可以真实运行并被量化。`result_ref` 对减少重复结果字节有效；但完整 structured 的字符、估算 Token、总传输负载和耗时均存在额外成本。后续优化应针对 handshake 复用、批量记忆查询、状态缓存和更贴近真实 Prompt 的字符统计，而不是修改数据制造优势。

## 14. 与真实 DeepSeek 演示的区别

另外完成的一次 DeepSeek structured 演示使用 `deepseek-v4-pro`，四个 Agent
依次执行成功，得到9条消息、估算 Token 1040、JSON 7734 B、MessagePack
7002 B、SemanticState 3次/384 B、共享记忆命中15条，总耗时28107.309 ms。

这条结果只用于证明真实模型接线、结构化协议、状态传递和共享记忆能够共同运行。
约28秒主要受外部网络和模型推理影响，不能与 Fake 的毫秒级耗时直接作性能对比，
也不能替代五组×10轮×6任务的300条离线 Benchmark。项目不宣称 structured
在所有任务中都比 text 更快；其主要价值是协议约束、能力发现、状态 ID、
`result_ref`、证据追踪和跨任务共享记忆。
